# 📅 서브컬처 게임 일정 대시보드 (Schedule Engine Architecture Guide)

본 문서는 대시보드 서비스의 **일정 관리 구조, 데이터 흐름, 3단계 자동 예측 연산 엔진 및 UI 표기 메커니즘**을 다른 개발자나 관리자가 한눈에 이해할 수 있도록 상세히 설명하는 아키텍처 문서입니다.

---

## 1. 개요 및 설계 철학 (Overview & Design Philosophy)

### 1.1 프로젝트 목적
원신, 붕괴: 스타레일, 젠레스 존 제로, 명조: 워더링 웨이브, 명일방주: 엔드필드 등 **주요 서브컬처 5종 게임의 패치, 공식 방송, 오프라인 이벤트 스케줄을 한곳에서 통합 제공**하는 웹 대시보드입니다.

### 1.2 아키텍처 철학: 하이브리드 안정성 중심 설계
- **복잡한 백엔드/DB 의존성 배제**: RDBMS/NoSQL 서버 관리가 일으킬 수 있는 가동 중단, API 호출 제한, 지연 시간을 방지하기 위해 **정적 JSON 파일 스토리지 기반**으로 구축되었습니다.
- **AI 파트너십 & 고효율 구축**: AI 에이전트와의 협업으로 신속히 구현되었으며, 일일이 수동 관리하는 번거로움과 일부 고정 데이터(하드코딩) 방식을 채택하는 대신 **사이트 가동 안정성 및 데이터 정확도 100%를 최우선**으로 삼았습니다.
- **수동 확정 + 자동 예측 하이브리드 시스템**: 확정된 공지사항 데이터는 정확히 노출하되, 아직 발표되지 않은 미래 일정은 게임별 고유 패치 패턴 규칙에 따라 **알고리즘이 유연하게 겹침 없이 자동 예측**합니다.

## 3. 데이터 구조 및 관리 체계 (Data Architecture)

일정 시스템은 총 4개의 핵심 데이터 소스가 유기적으로 연결되어 동작합니다.

```
[ gamesConfig.js ] ────────┐
                           │
[ schedule_data.json ] ────┼──> [ useScheduleData.js ] ──> [ scheduler.js ] ──> [ UI Render ]
                           │   (ID 기반 Merge & Override)   (3단계 예측 연산)      (Gantt / List)
[ schedule_updates.json ] ─┤
                           │
[ schedule_hints.json ] ───┘
```

### 3.1 `src/config/gamesConfig.js` (게임 마스터 기본 설정)
- 게임별 기본 고유 속성을 관리합니다.
- **포함 정보**: 공식 명칭, 단축어, 대표 테마 색상(Hex/RGB), 공식 웹사이트/유튜브 링크, 기본 패치 주기(`cycle`: 보통 42일), 반주기(`halfCycle`: 보통 21일), 공식방송 오프셋(`streamOffset`: 보통 -12일), 기본 대표 이미지.

### 3.2 `public/data/schedule_data.json` (베이스 스케줄 데이터)
- 과거부터 누적되어 온 기초 일정 히스토리 및 서버 차원의 기본 주기 정보를 보유합니다.

### 3.3 `public/data/schedule_updates.json` (실시간 수동/확정 업데이트)
- 새로 발표되는 공식 공지사항(공식방송 확정, 신규 버전 전/후반 일정, 오프라인 이벤트 등)을 주입하는 가장 중요한 파일입니다.
- **핵심 필드**:
  - `id`: 고유 식별자 (예: `EVT_GNS_20260731_0001`)
  - `is_fixed`: `true` (확정 이벤트임을 명시 ➔ 예측 엔진이 덮어쓰지 않음)
  - `detail`: 픽업 캐릭터, 신규 코스튬, 보상 등의 상세 텍스트
  - `custom_img`: 해당 이벤트 전용 썸네일/배너 파일명 (`.webp`)
  - `ticket_links`: 오프라인 예매처 링크 배열

### 3.4 `public/data/schedule_hints.json` (예측 오버라이드 힌트)
- 패치 주기가 바뀌거나 버전 번호가 일반적인 `X.Y -> X.(Y+1)` 수순을 벗어나는 예외 케이스를 제어합니다.
- **제어 기능**:
  - `trigger_version`: 힌트가 작동할 기준 버전
  - `next_version_number`: 다음 버전 번호 강제 점프 (예: `4.8 -> 5.0`)
  - `cycle_override`: 특정 버전만 49일 등으로 기간 변경 시
  - `stream_date_override`: 특정 방송 일자 강제 지정

### 3.5 데이터 병합 파이프라인 (`useScheduleData.js`)
1. 10분 단위 브라우저 캐시 타임스탬프(`?t=...`)를 활용해 정적 JSON 파일들을 병렬 `fetch`합니다.
2. `schedule_data.json`의 베이스 데이터 위에 `schedule_updates.json` 데이터를 **ID 맵(Map) 기반으로 덮어쓰기(Merge & Override)**하여 무결성을 유지합니다.
3. 병합된 확정 데이터를 `scheduler.js` 예측 엔진에 전달합니다.

## 4. 스케줄 예측 & 보정 알고리즘 (`src/engine/scheduler.js`)

예측 엔진은 확정된 일정의 이후 미래를 3단계 우선순위에 따라 자동으로 연산하여 생성합니다.

### 4.1 3단계 우선순위 메커니즘
1. **1순위 (확정 데이터, `is_fixed: true`)**: 관리자가 주입한 실시간 데이터. 알고리즘이 절대 수정하거나 삭제하지 않고 원본 그대로 유지합니다.
2. **2순위 (힌트 데이터, `schedule_hints.json`)**: 예외적인 패치 주기 변경, 방송 날짜 변경, 버전 번호 점프 규칙을 우선 반영합니다.
3. **3순위 (패턴 연산 데이터, `gamesConfig.js`)**: 기준일로부터 기본 주기(`cycle: 42일`)를 더해 미래의 전반/후반/공식방송 이벤트를 생성(`is_fixed: false`)합니다.

### 4.2 예외 및 연장 겹침 자동 보정 로직
- **특정 버전 기간 연장 대응 (`end_date` 보정)**:
  - 주년/반주년 행사 등으로 특정 버전의 `end_date`가 명시되어 평소 주기보다 기간이 길어진 경우(예: 엔드필드 1.4 버전 9월 1일까지 연장), 예측 엔진은 차기 버전 시작일이 이전 버전의 종료일 이전이 되지 않도록 **`end_date + 1일`로 자동으로 다음 시작일을 뒤로 밀어 이격**시킵니다.
- **특정 게임 요일 보정 (엔드필드 특화)**:
  - 엔드필드 패치 요일이 목요일로 고정됨에 따라, 자동 연산 결과가 금요일에 걸칠 경우 하루를 당겨 목요일로 맞추는 보정이 작동합니다.
- **전반/후반 렌더링 기간 연쇄 연동**:
  - `getEventDuration()` 함수가 전반업데이트의 종료일을 다음 확정 전반업데이트 시작 전날로 동적 계산하며, 후반업데이트의 기간 역시 전반업데이트의 실제 종료일에 맞춰 자동으로 연동되어 길이가 줄거나 늘어납니다.

## 5. UI 표기 및 컴포넌트 매핑 (UI Component Architecture)

가공된 전체 이벤트 배열(확정 + 예상)은 뷰 포맷에 따라 화면에 다르게 표기됩니다.

### 5.1 간트차트 뷰 (`src/views/GanttView.jsx`)
- **날짜 축 생성**: 오늘(Today)을 기준으로 과거 30일 ~ 미래 90일(총 121일)의 날짜 축을 형성합니다.
- **자동 오늘 스크롤**: 최초 진입 시 마우스나 화면이 자동으로 '오늘(Today)' 위치의 중앙으로 스크롤됩니다.
- **시각적 구별**:
  - **확정 이벤트 (`is_fixed: true`)**: 게임별 테마 컬러가 꽉 찬 **실선 바(Solid Bar)**로 표시됩니다.
  - **예상 이벤트 (`is_fixed: false`)**: 슬레이트 그레이 톤의 **점선 테두리 바(Dashed Bar)**로 표기됩니다.
  - **공식방송**: 라디오 아이콘과 `LIVE` / `예상` 깃발 형태로 상단에 플로팅 표기됩니다.
  - **오프라인 이벤트**: 핀(📍) 아이콘과 함께 투명도 들어간 아웃라인 카드로 표시됩니다.
- **성능 최적화**: 화면 밖의 그리드 돔 렌더링 부하를 지우기 위해 `.gantt-row`에 `content-visibility: auto` CSS 속성이 이식되어 있습니다.

### 5.2 리스트 뷰 (`src/views/ListView.jsx`)
- 모바일 기기(768px 이하) 접속 시 기본 뷰로 지정되는 카드 타임라인 레이아웃입니다.
- 날짜순으로 타원형 노드와 함께 일정이 세로로 정렬되어 직관적으로 보여집니다.

### 5.3 상세 모달 (`src/components/DetailModal.jsx`)
- 차트나 리스트에서 이벤트를 클릭하면 모달 팝업이 열립니다.
- 버전 명칭, 확정 여부 배지, 커스텀 이미지, 상세 픽업/이벤트 텍스트, 예매처 링크 등이 노출됩니다.
- **모바일 뒤로가기 연동**: 브라우저 뒤로가기(`popstate`) 시 페이지가 이탈하지 않고 모달 팝업만 자연스럽게 닫히도록 히스토리 제어가 되어 있습니다.

## 6. 유지보수 및 일일 운영 가이드 (Operations & Maintenance)

### 6.1 신규 확정 일정 업데이트 방법
1. `public/data/schedule_updates.json` 파일 상단에 새 JSON 객체를 추가합니다.
2. 예시:
   ```json
   {
     "id": "EVT_GNS_20260731_0001",
     "game": "원신",
     "version": "7.0",
     "type": "공식방송",
     "title": "7.0 버전 특별 방송",
     "date": "2026-07-31",
     "end_date": "2026-07-31",
     "time": "21:00",
     "is_fixed": true,
     "detail": "상세 내용...",
     "custom_img": "genshin_7.0_stream.webp",
     "link": "https://..."
   }
   ```
3. 별도의 서버 재시작 없이 브라우저 새로고침(또는 빌드 후 배포)으로 즉시 반영됩니다.

### 6.2 신규 이미지 등록 수칙 (`.agents/rules/images.md`)
- 신규 이미지는 `c:\Users\keybo\Desktop\Project\Agent\파일 첨부` 폴더에 넣고 작업합니다.
- 파일명은 영문 소문자 + 언더스코어 조합의 `.webp` 확장자로 통일(예: `genshin_7.0_stream.webp`)합니다.
- 용량 최적화를 위해 WebP 품질 80% 압축 과정을 거쳐 `public/assets/` 폴더에 저장합니다.

## 7. 요약

본 대시보드는 **"단순함 속의 높은 안정성"**을 지향합니다. 복잡한 백엔드 기반 대신 정적 JSON과 React의 조합으로 속도와 무장애 가동성을 확보했으며, 정밀 설계된 **3단계 예측 엔진(`scheduler.js`)**을 통해 최소한의 수동 데이터 입력만으로도 미래 스케줄을 완벽하게 계산해내는 시스템입니다.
